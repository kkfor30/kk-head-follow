# 能力与证据

当前能力是“视频姿态环 → 图集 → 鼠标方向取帧”。一圈姿态支持方向随动；距离只参与中性区，不能从一圈视频推导独立转头幅度或单独眼球运动。

- 生成器：可选的素材入口，按显式次数预算提交，旧任务查询不占次数。
- 分层静态合成器：完整透明角色与背景共用坐标，生成静态图和逐主体干净底图；绑定输入和输出哈希，不自动判断光照、落地感或视觉验收。
- 分析器：媒体规格、像素运动报告与采样接触表；不自动认方向。
- 编译器：保持比例、按源帧索引组装路线、局部背景处理、输出可追溯图集。
- 校验器：底图/视频哈希、尺寸、有效帧、严格方向锚点、图集容量、背景数据。
- 运行时：实际图像位置计算指针角度、几何角度阻尼、独立主体绘制、回正清层与生命周期回退。

## 不能混淆的验证

1. 脚本单元测试：已知错误被拒绝、索引映射和算法符合约定。
2. 已有案例复现：相同视频和标定重编译，逐帧像素及鼠标轨迹与原实现比较。
3. 新素材生产：重新准备输入、生成、标定、合成并由用户验收。

完成第 2 项不代表已证明任意新图片都能成功，也不证明视频模型的生成成功率。

独立角色动作、目标首屏静态融合、真实页面动态融合是三项不同结论。独立角色实验支持继续验证分层首屏，不证明新角色头颈能接回完整旧照片。新建首屏优先分层制作；旧照片局部替换是进阶路线。素材复用和通用脚本能力不能把个例人工拼接包装成自动修复。

不要把项目数字写成全局规则。眼睛位置、crop、upperMidpoint、阻尼与羽化由主体配置。项目验收记录由各项目独立保存，Skill 不依赖私人角色素材、仓库路径或作者会话。可选示例只展示方法，不作为新用户的默认输入；示例标定不得复用于不同图片。


## 当前工程检查的边界

修复器提供有边界的配准、校色、干净背景合成、裁段和单来源光流候选，不自动证明姿态和眼神正确。audit_head_atlas.py 将结构、逐帧背景数值、Agent 观察和交互证据分别记录；任何缺项保留 blocked。它不是通用自动人脸/动物姿态或残影识别模型。

正式 runtime 默认要求内容匹配的质量报告；诊断预览显式 opt-in。修改图集、方向索引、底图或参数后旧观察失效。失败先修复再复查，不只写报告等待用户找错。
