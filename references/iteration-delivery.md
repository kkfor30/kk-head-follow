# 首轮候选与用户驱动迭代

目标是先在用户要求的真实场景中提供诚实、可体验的候选，再根据用户反馈修复。首次生成不保证完整或完美；两三轮是可接受的迭代空间，不是默认生成次数或成功保证。

先按 [feasibility.md](feasibility.md) 排查主要瓶颈。候选分级描述当前能体验什么，不改变用户原目标；phase 不能算准确方向跟随完成，arc 只满足已接受的方向范围。缺方向时先处理素材，背景不匹配时先做代表帧合成；不要先批量补帧、抠像再判断是否值得继续。

## 首轮

已有视频直接进入母版初筛与代表帧合成，跳过下面的新生成规划和提交；不为走完流程而重新生成。

1. 先按 generation-planning.md 明确目标、控制来源、实际输入姿态、动作路线和合成方式，审查图片后再生成。全人物分层不等于必须全身生成；局部输入也不意味着可以直接拼回旧身体。任何裁切必须保留坐标和头颈运动余量。本规则不宣称绿幕、近景或某种首尾方案必然成功。
2. 默认预算仅一次 5 秒/768p 试片，用户明确的其他范围优先；复杂轨迹需要更长时长或分段时应调整计划及预算，不把动作硬塞进 5 秒。进入/有效环/退出须分别分配时间；完整环的8–10秒规划建议及限制见 generation-planning.md，不能据此自动增加预算。生成后先检查全片方向覆盖、身份、明显变形、持续闭眼和表情变化，再投入插帧、图集编译与细节修复。不要到第二版图集才发现母版缺失半圈。
3. 明确缺陷后先做一轮针对性的程序处理，比较原件与候选。只有有证据表明改善且下一步目标具体时才继续；同一缺陷连续两次程序处理无改善或引入更严重问题，保留较好版本并交付问题说明，不循环试算法。此停止条件不限制修复代码错误、缺文件等可确定解决的问题。
4. 交付下面适用的候选，说明实际完成范围、残留缺陷、生成次数和下一步。不得把“全部工程检查通过”作为所有预览交付的前提，也不得宣称候选已通过正式验收。

## 候选分级

| 源素材 | 交付方式 |
|---|---|
| 方向环基本完整，存在边缘、节奏或小接缝缺陷 | 结构校验后，在真实背景和布局的独立候选页使用 diagnosticPreview:true 提供鼠标体验；显式标注缺陷，并保留静态对比 |
| 仅部分连续真实方向可用 | preview.mode=arc，以实际观察标定 samples，标明有效方向区间；现有运行时区间外回静态。不得把半圈拉成整圈、伪造八个锚点或循环穿过缺口 |
| 动作连续、身份尚可，但主要歪头或方向不可准确标定 | preview.mode=phase，将鼠标角度映射为视频动作进度，展示“鼠标控制动作”并说明方向与眼神可能不对应；不命名为准确注视。跨首尾可能跳变，需披露 |
| 严重变形、裁断、身份不一致，或没有值得体验的连续动作 | 真实场景合成播放与静态对比，说明不能提供有意义的方向交互；保存失败证据用于修复 |

标准方向图集仍要求八个真实方向锚点。arc/phase 使用独立 preview 清单与 experimentalPreview:true，带资产哈希，不包含虚构方向，也不能审批为 ready。具体配置见 runtime.md。arc 的角度来自实际观察；phase 的角度只是交互进度，不是视频姿态证据。

原始母版、源帧、处理候选与已验收版本分开保存。用户要求实现交互已包含制作独立候选的授权，不必等用户说“硬接入”；有可用素材就完成适当候选。默认首页替换遵循用户原请求，不能改写质量记录为 ready。正式版本仍按 runtime.md 与 repair-and-review.md 检查。不能浏览器验证时如实记录，完成可执行的离线检查并提供入口，不声称体验通过。

## 后续修复与生成预算

- 用户指出问题后，先定位源动作、映射、合成或运行性能；程序可修则直接处理，不反复索要已具备的授权。
- “这里卡顿/有残影”本身不等于允许新增付费视频。缺失源动作需要生成时，先说明要补什么、使用什么首尾、拟新增次数与时长，再按已有明确授权执行；没有授权才询问。用户明确要求重新生成则不重复确认。
- 同一项目、同一效果任务使用唯一的共享预算文件，默认 build/generation-budget.json。pilot、repair、重试都累计；子目录不能自建预算重新获得次数。已有任务沿用原预算，不迁移清零。
- 后续获授权时，在同一预算保留 attempts，记录用户授权内容及本轮用途，增加相应 maxSubmissions、maxTotalSeconds 等限制，并记录 limits.changeReason。授权一条补片不等于授权无限补片。查询已有 job 不算新生成。
- 启动前检查该任务已存在的预算和 submission.json；若此前分散记账，先汇总核对，不能把旧次数视为零。目前脚本只约束传入预算文件，跨文件预算归属仍依赖 Agent 遵守本规则；不得宣称程序已全局阻止绕过。
- 补片先验动作与表情，再拼接。接点绑定实际参考帧，检查两侧多帧运动趋势；复制第一帧到末尾不是闭环通过证据。每轮修复复查目标缺陷及新增副作用，不为未变素材重复整套无关检查。

完整交付路径是“首轮有限成本候选 → 用户反馈 → 定点程序修复或获授权的新生成 → 同场景对照”。缺陷记录和静态回退是保护措施，不替代本来能够完成的候选交付。
