# 分层首屏：先静态融合，再制作动作

## 制作顺序

1. 确认构图参考里的角色位置、相对大小、姿势、镜头方向、光照和文字留白。参考图是设计依据，不直接充当后续动态页的唯一底图。
2. 准备不含动态角色的背景，每个完整角色各一张真实透明素材。必要的接触阴影单独保存；遮挡角色的前景单独规划层序。已有正确分层素材直接复用，不为流程重复生成。
3. 把实际素材按统一坐标拼成静态首屏；检查风格、比例、光照、脚底接触、阴影、文字与角色的关系。用户已有同版验收则复用；没有则展示具体合成供验收，不用“文件存在”代替。最终静态图由这些层合成，不再另生成一张外观不同的整图。
4. 单主体默认一次 5 秒小样。抬头首尾参考应来自已确定角色；如经生成修改，应先放回静态首屏检查身份和比例。源视频核验完整轨迹、视线、身体接触点和幅度；RGB 视频仍需去背景，透明参考不保证透明输出。
5. 检查源片后裁段、标定、比较原生与 2× 补帧、制作 Alpha 图集。完整角色作为一层显示；不因想保留另一张照片的身体，临时切掉新素材下半身拼接。身体漂移仍要单独检查，分层不能修复源片形变。
6. 在第 3 步的实际首屏接入一名角色，检查动态/休息态切换、全方向、顶部反向、接触点、邻近角色和遮挡，再扩展其他主体。纯色对照页只帮助定位抠像和动作问题。

静态层已融合、角色动作已可用、真实首屏动态已验收分别记录。一次独立组件的成功不等于复杂场景成功；旧图局部替换仍按 background-delivery.md 处理。

## 可重复的静态合成

`compose_layered_scene.py` 接受不透明背景与带 Alpha 的图层，输出同尺寸的 `static.png`、每个主体的 `clean-ID.png` 及 `scene.json`。underlay 可用于预制阴影；subject 是整角色。所有路径相对 --root，以下尺寸仅示意，必须换成当前素材坐标：

```json
{
  "sceneId": "living-room-v1",
  "background": "source/room-empty.png",
  "layers": [
    {"id":"contact-shadow","kind":"underlay","image":"source/shadow.png","rect":[600,680,240,80]},
    {"id":"character","kind":"subject","image":"source/character-alpha.png","rect":[560,260,320,480]}
  ]
}
```

rect 为原背景像素中的 [x,y,w,h]，必须保持源图比例并预留完整运动余量。脚底或座位接触点要在制作记录中标定；不把示例位置当通用数值。脚本不能识别图中是否已经有旧角色，需查看背景。

```text
python scripts/compose_layered_scene.py build source/scene-spec.json --root PROJECT --output PROJECT/build/static-v1
python scripts/compose_layered_scene.py verify PROJECT/build/static-v1/scene.json --root PROJECT
```

verify 核对输入、几何记录和输出哈希；素材变化后重新合成。它不颁发视觉证书，也没有自动阻止视频 API 提交，执行者须按上述顺序检查。脚本不覆盖旧输出。休息态是输入角色的实际姿态；头朝上就写抬头，不能称为正视中性。

接入现有编译器时，baseImage 指向 `static.png`，cleanPlate 指向当前主体的 `clean-ID.png`，sourceSize 为背景尺寸，crop 对应角色最终绘制区。视频 renderSize/motionCrop 按真实视频尺寸与输入留白标定；静态角色 rect 不自动等于生成视频的裁切参数。背景页不得同时再显示一份旧角色。

## 范围与限制

- 合成器支持完整角色、先于角色绘制的静态 underlay、不重叠的角色矩形。它不生成图片、阴影、逐帧 Alpha 或新姿态，也不做局部头颈修复。
- 多个动态角色或前景遮挡需要保持正确层序。现有局部 canvas 会重画各自 cleanPlate，绘制矩形重叠时可能互相擦除；脚本拒绝这种静态配置进入现有接入方案。不要缩小必要运动边界绕过错误。需要重叠时采用共同 scene renderer，作为另外的实现与验证工作。
- 接触阴影可随背景保留，但需要随姿态变化的阴影必须独立处理。均匀绿幕不能自动保留真实场景投影。
- 静态回位图与动作首帧若来自不同缩放、色键或生成版本，会产生切换差异。对照真实最终合成，必要时用同一预处理方式生成静态角色和动态图集；保持来源记录。
- 不在通用 Skill 中附带私人素材、案例路径或声称全自动验收。示例资产如另行发布，应有可分发许可、完整输入和标定记录，并标明只代表该例。
