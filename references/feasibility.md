# 尽早判断能否完成方向跟随

先明确用户要的是鼠标方向对应的真实转头，还是只需角色对鼠标有反应。没有特别说明时，头部/视线跟随按前者处理。phase 只是鼠标控制播放进度，不能作为方向跟随已完成；arc 只满足用户接受的有效方向区间。不要因为某种预览能交付，就把原目标悄悄降级。

## 先选择可控的实现路线

| 已有条件 | 优先动作 |
|---|---|
| 同身份、同场景的已标定可用图集 | 核对来源和坐标，复用并接入；不要重新生成 |
| 连续视频尚未检查 | 先检查原生动作覆盖，再制作图集 |
| 只有静态图，接受生成结果的不确定性 | 单主体试片，尽早判断素材能否承担目标 |
| 必须准确控制独立眼球、幅度或任意方向的自然回正 | 评估有对应控制能力的二维/三维绑定方案；当前视频图集不提供这些自由度 |

绑定方案需要可用的分层/模型和制作工作，不是自动把任何照片变成可控模型。用户已选视频方案时，保留其选择并说明具体缺口，不擅自改技术路线。已有素材足以完成时直接实施，不加新审批。

## 在精修之前检查母版

默认逐主体验证。新生成一条请求只驱动一个目标，静态邻居或场景可保留作上下文；已有同屏视频则分别检查各主体，不因旧片含多角色而丢弃。生成输入与最终页面分开：保持身份、眼睛清晰度和头颈余量，背景路线按 [scene-routing.md](scene-routing.md) 选择。一次预算只够一个主体时，先验证这一条链路，并说明其余范围。

没有现成的逐帧记录时，可用低分辨率原生帧检查先判断方向缺口：

```text
python scripts/review_source_video.py --video PROJECT/source/result.mp4 --crop X Y W H --output PROJECT/build/source-review
```

crop 是原视频坐标。输出所有原生帧的接触表、带实际源帧编号与时间的 JSON、区间内往返 WebP；不编译正式图集、不插帧、不生成新素材。缩略图用于找动作，眼神不清楚时检查原像素。往返播放不能证明首尾可闭环。已有充分证据时直接复用，不为流程重新导出或重复填表。

先看最多 24 个采样帧的 overview.jpg，用于发现明显缺口；它不代替全帧检查。JSON 将头部与眼神按方向分开留空，另记表情和中性兼容性；不因头部能转就把眼神判通过。自然进入/退出和精确注视见 [gaze-and-rest.md](gaze-and-rest.md)。

逐页检查之后，在同一份 source-review.json 或已有制作记录里写清：可用帧区间与实测方向、缺失方向、身份/表情、身体和背景变化、首尾衔接。不能由光流量、时间比例或文件存在自动判为通过。

| 观察到的情况 | 下一步 |
|---|---|
| 所需方向与身份可用 | 用原生帧立即制作真实场景候选；体验显示采样不足时才补帧 |
| 缺少一个动作区间 | 记录具体缺口，复用真实片段或在已有授权内准备针对性补片；不要做全套抠像、补帧来解决方向缺失 |
| 只有歪头/左右运动，没有所需上下动作 | 如有诊断价值，可交付明确标注的 phase；原方向目标仍未完成，不继续精修成“准确跟随” |
| 动作有用，背景或颈部不匹配 | 先在最终背景合成几张代表帧，确认静态融合可行后再批处理全片 |
| 身份漂移、截断或没有可用连续动作 | 保留失败证据，修输入/控制路线；停止在该母版上尝试不同补帧算法 |

用 [scene-samples.md](scene-samples.md) 的脚本导出几张真实场景代表帧。这是早期筛查，不替代最终全帧检查。重点覆盖最大侧转、抬/低头、颈根和最差边界；不要只挑最好看的帧。

## 每轮只解决一个已定位的瓶颈

鼠标映射错就修映射；真实姿态缺失就补真实素材；身体/背景接不上就处理合成。不要靠调阻尼修缺方向，也不要因为网页挂载错误重生成视频。

缺口未改变时不做同配置付费重试。下一次生成应有具体改变，例如新的动作参考、修正首尾姿态或仅补缺失区间，且仍受原共享预算约束。未证明参考或分段更有效时，不宣称它们必然成功。

交付同时报告“用户原目标完成程度”和“当前候选类型”，注明付费次数与主要耗时。首轮检查只证明这份母版是否值得继续；新的生成成功率需要实际跨素材记录，工程回归通过不能代替它。
