# 从失败现象到下一步制作

先对照原生视频、代表帧合成与鼠标映射，确定问题发生在哪一层。保留可用部分和原始身份基准；新生成沿用原预算。下一次若仍不能改变实际输入或控制方式，不重复同配置提交。

| 实际证据 | 优先修法 | 验证重点 |
|---|---|---|
| 完整方向都有，局部停留或速度变化 | 剔除无效停留、按真实运动重新标定；必要时生成 phaseSamples 候选 | 剔除后新邻接是否跳变、顺逆向是否一致 |
| 顶部卡顿，路线掺入正脸/回正 | 先排除进入与结束段；若仍缺上弧，准备单独 upper-arc | 抬头高度、两侧接点、顶部前后运动趋势 |
| 完整片反复漏同一方向 | 换已核验动作示范或最少必要 segment；保留已可用区间 | 新片确实经过缺失方向，身份仍匹配 |
| 头朝向正确，眼睛盯镜头或乱飘 | 检查原眼睛可见性和图文冲突；补能看清虹膜的近景/示范，再按缺口重做 | 分别检查眼神、转脸、眼皮与表情；不能只改方向标签 |
| 运动完整但原生采样少 | 先检查帧映射；需要时比较原生与 2× 插帧 | 眼睛、发丝和遮挡不产生双影；不过量补帧 |
| 动作好，背景差 | 用真实场景代表帧选择有限校色/配准，或 Alpha + cleanPlate | 背景纹理、旧头轮廓与颈根；不重新生成动作解决网页色块 |
| 只在页面跳帧，素材双向离线播放正常 | 检查图集解码、角度最短路径、DPR、预载和事件生命周期 | 使用实际显示尺寸；不通过重生成视频修挂载或映射错误 |
| 中性表情与运动不兼容 | 先保证身份、嘴部和表情一致；中性进出另备真实过渡 | 静态切换、连续过渡分开报告，不用跨脸叠化制造残影 |

## 只修顶部

1. 在主片中找已核验的左上、右上姿态和前后相邻帧；不要使用身份漂移或视线错误的帧作为“正确参考”。输入需要重做时始终对照原始身份。
2. `motionPlan.kind=upper-arc`，`startDirection=upper-left`、`endDirection=upper-right`，真实首尾分别提交左上/右上图。整片只做左上→上→右上，持续抬头，明确不要经过正脸。不是再生成完整环。
3. 用 promptSpec 派生提示词；requirements.motion 和 loop 同步改为上弧、非闭环，不能残留完整一圈的要求。依据见 [prompt-patterns.md](prompt-patterns.md)。
4. 先检查上弧与主片三组接点的多帧趋势，再用 [asset-contract.md](asset-contract.md) 的 upperVideo 编排。顶部来自同片相邻帧，但两侧跨源接点仍可能突跳。

接回上弧时，正上方取实测姿态，不默认取视频时间中点。先保留接点附近连续帧；裁掉“静止段”也可能破坏姿态衔接。若裁切引入跳变，恢复原帧，对已观察的近乎停留区间用 phaseSamples 压缩鼠标角度跨度，再检查双向接缝；不要跨脸淡化，也不照抄其他角色的帧号或角度。phaseSamples 在此是完整方向环的节奏标定，不是用实验 phase 假装方向完整。

一次人物深色场景实测中，5秒中性进入完整环缺少左上至正上；另补5秒左上→上→右上的真实首尾片段后，用户确认效果可用。补片正上方晚于时间中点，裁开头导致轻微接点跳变，恢复原帧并压缩停留区间后交付。该例支持定点补弧与实帧标定，不证明更长首片一定避免补拍；原片低头眼睛、轮廓与静态回正的局限仍需分开记录。

## 修眼神或幅度

头部和眼神分开写 expected。用鼻尖/双颊可见变化说明 yaw，用下巴升降说明 pitch；可见虹膜/瞳孔应朝同一个屏幕方向。避免“全程看镜头”与“跟随画外目标”同时出现。保留表情不等于固定眼球。

输入眼睛像素过少、墨镜遮眼、毛发遮眼时先解决可见性；不能从鼻尖方向推定眼神。原图看镜头可以是中性起点，外围动作应改变注视方向。原图为侧面时按可见眼睛和用户需要的范围处理，不强求凭空露出另一只眼。

若只有一个区间眼神错，优先修该区间；整片错则考虑新的清晰输入或合适动作示范。下一次生成须说明实际控制变化和要复核的源帧，不只把“眼睛必须跟随”重复多遍。

## 快速判定与停止投入

每轮先运行原生动作总览，再运行真实场景样片。完整性不足时不先做全片抠图；合成不可行时不先打包大图集。连续同类程序处理没有改善时按 iteration-delivery.md 停止该尝试，保留较好候选与明确缺口。浏览器未验收就保持未验收；离线诊断继续完成。
