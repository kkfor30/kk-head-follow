# 生成控制与输入检查

先复用可用素材；只有需要生成时走本文。目的在于减少模型猜测，不是靠事后拦截提高表面通过率。

## 控制分工

| 要求 | 优先控制 | 边界 |
|---|---|---|
| 身份、服饰、构图 | 原始身份基准与一致的参考图 | 失败帧的漂移不能成为新基准 |
| 起始与终止姿态 | 实际首尾图 | 同图首尾不限定中间路线，也不保证接缝速度 |
| 方向顺序、幅度、头眼协调 | 动作示范，必要时分段关键帧 | 是视觉引导，不是骨骼/眼球硬控制 |
| 允许变化、限制 | 与图一致的动作描述 | 文字角度、秒数不是精确执行参数 |
| 固定背景与布局 | 原图/分层素材及程序合成 | 头颈衔接与遮挡仍需检查 |
| 节奏、鼠标响应 | 实片标定与运行时 | 不能创造缺失方向或眼神 |

不把小幅度、零侧倾、上下对称、闭嘴或微笑写成通用外观。按用户目标、主体结构、原始姿态和最终显示尺寸确定范围，表情和嘴部状态沿用实际输入。自然回正、独立眼球与按距离改变幅度是独立需求，外围方向环不提供这些路径。

## 选择路线

- **closed-orbit**：有合适的已检查抬头接缝图，实际同图作首尾。正式图集目前以向上为零点；改接缝方向需同时扩展编译标定，不只改字段。
- **entry-orbit**：只有中性图且允许进入段。时长包含进入和完整一圈，进入段按实片排除，不能强行裁成环。
- **reference-motion**：动作顺序/头眼配合是主要难点，且有适合目标主体的示范。参考图负责身份、视频负责动作，referenceRoles 写清实际文件顺序与用途。参考模式与首尾模式互斥，不保证精确端点。
- **segment / upper-arc**：必须经过指定姿态，或反复缺少一段真实动作时，使用最少必要片段。首尾图片不说明从哪一侧经过，仍要写 via。多段增加费用、漂移与接缝，不默认拆八段。当前接口没有带时间戳的中间帧字段，九宫格和多张参考图不是中间帧硬约束。
- **diagnostic**：定位某个轴或输入可动性，不能替代完整跟随交付。

5秒/768p是低成本试片默认，不是所有动作的最佳值。时长按所选模型范围、动作与已有预算决定。参考视频、绿幕、近景、分段或更长时长都没有跨素材成功率保证。

## 一份规格派生提示词与验收

motionPlan.requirements 包含 identity、motion、range、gaze、fixedParts、loop、rest 七项，每项：
```json
{"expected":"可观察目标或明确未请求的能力","controls":["prompt","first_frame"],"verify":"在哪个阶段、用什么证据核对"}
```

controls 可用实际发送的 first_frame、last_frame、reference_image、reference_video、reference_audio，或 prompt、compositing、runtime、not-requested。未实际发送的媒体不能声称为控制来源。仅靠 prompt 的项会在 dry-run 提示，不增加审批。compositing/runtime 在 expected/verify 中写具体处理；rest 未实现时写静态回退，不写自然回正。

motionPlan 不发给模型，Agent 据此编写 prompt 并沿用同一验收标准。脚本验证结构、引用和哈希，不自动证明文字语义完整或视觉正确。

## 请求绑定的输入观察

用生成器 --write-input-review 创建 JSON，见 zenmux.md。模板记录实际请求哈希、媒体字节哈希、尺寸与原始身份基准，语义状态均为 unreviewed。Agent 查看实际输入后填写：

| 检查 | 内容 |
|---|---|
| identity | 各输入与原始基准一致，未继承失败帧变形 |
| inputPose | 实际姿态与声明首尾/参考角色一致 |
| motionRange | 幅度适合当前主体和用途，未拿极端姿态当通用端点 |
| featureVisibility | 所需眼睛、脸、耳等能看清；不可见部分明确未知 |
| framing | 头颈完整、运动余量、比例和目标显示清晰度 |
| fixedParts | 身体位置、尺寸与最终合成路线相容 |
| promptImageAgreement | 图文无冲突，无虚构视觉约束 |
| endpointCompatibility | 起终态可衔接，同图闭环与中性进入区分正确 |
| motionReference | 示范本身方向、幅度、眼神与镜头适用；无示范则 not-applicable |

status 为 pass / limited / not-applicable / fail / unreviewed；已判断项须有具体 notes。limited 记录可接受输入局限，不代表生成质量；若核心要求已不可能则写 fail 并修输入。不要自动把全部模板填 pass，也不要让用户代填 Agent 能完成的观察。已有用户验收可引用。

改图、改请求或计划后保留旧表并创建新表；只重新核对变更影响，其它有效观察可注明来源后沿用。哈希不证明语义，观察表不是批准来源。原始身份基准也绑定字节，防止逐轮漂移被合理化。

对像素级固定背景复用原图，对精确关节或独立眼球控制选择有对应控制能力的制作方法。模型没有相应接口时说明精度边界，不能用更多“必须”承诺确定性。
